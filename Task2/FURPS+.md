| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| F   | **Функциональные (Functionality)** | |
|     | На сайте новый клиент видит список доступных депозитов с актуальными ставками | |
|     | На сайте клиент может оставить заявку на депозит (ФИО, телефон) — менеджер кол-центра перезванивает и при необходимости предлагает особые условия | |
|     | В интернет-банке клиент видит список доступных депозитов с актуальными ставками и персонализированными ставками | |
|     | В интернет-банке клиент может подать заявку на открытие депозита, указав счёт и сумму, с подтверждением через СМС-код | |
|     | Сотрудники бэк-офиса депозитов и бэк-офиса кредитов могут управлять ставками по депозитам (предпочтительно через АБС) | Сейчас ставки хранятся только в XLS-файлах |
|     | На этапе MVP менеджер бэк-офиса обрабатывает заявку вручную и подтверждает условия в АБС | |
|     | Клиент получает СМС-уведомления после подтверждения ставки и после открытия депозита | |
| U   | **Удобство использования (Usability)** | |
|     | Интерфейс подачи заявки и работы с депозитами должен быть максимально удобен для клиента | Основная аудитория банка — пожилые люди |
|     | Все экраны должны соответствовать дизайн-системе банка: привычные цвета и фирменные элементы | |
|     | Время отклика на все пользовательские действия — миллисекунды | Текущая загрузка справочных данных при платежах занимает более секунды |
| R   | **Надёжность (Reliability)** | |
|     | Все сервисы должны работать 24/7 с доступностью 99,9% | |
|     | При сбое в основном ЦОД интернет-банк должен оставаться доступным через резервный ЦОД | Резервный ЦОД уже существует |
|     | Недопустимы прямые вызовы из интернет-банка в АБС для новых процессов | База АБС перегружена; онлайн-подача заявок на большое количество продуктов может поставить под угрозу работоспособность банка |
| P   | **Производительность (Performance)** | |
|     | Интернет-банк должен поддерживать горизонтальное масштабирование: балансировка нагрузки между серверами, приложениями и дата-центрами | Сейчас работает на одной группе серверов в одном ЦОД — требование 99,9% не выполняется |
|     | АБС масштабируется только вертикально (ограничение СУБД) — архитектура новых процессов должна учитывать этот предел | |
| S   | **Поддерживаемость (Supportability)** | |
|     | Использовать максимум существующих технологий (MS SQL, Oracle); новые технологии должны быть совместимы с текущими платформами разработки | |
|     | Все изменения должны быть задокументированы с прицелом на будущее расширение системы | |
|     | Для депозитного модуля интернет-банка рассматривается переход на микросервисную архитектуру | Kafka несовместима с текущей версией платформы интернет-банка; её использование — на перспективу |
|     | Функциональность SMS-кода предпочтительно реализовать силами команды банка (текущая реализация в АБС требует подрядчика) | |
| +R  | **+ Ограничения (Restrictions)** | |
|     | Персональные данные на сайте и в интернет-банке должны передаваться в зашифрованном виде | |
|     | Новые клиенты обязаны лично явиться в отделение для идентификации | Законодательное требование: банки не вправе принимать новых клиентов без очной проверки документов |
|     | Экспертиза по используемым технологиям должна быть в банке | |
